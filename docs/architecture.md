# 架构与实现边界

## 当前阶段

模块化单体。Vaadin 页面、领域服务、浏览器会话和文件存储运行在同一 JVM，避免在多人浏览器隔离与截图一致性尚未验证时过早拆分服务。

## 权威数据源

- `local`：本地 JSON 为权威数据源，文件先写临时副本再替换。
- `postgresql`：PostgreSQL 为唯一权威数据源，本地 JSON 不参与业务写入。
- 两种模式都使用文件系统保存截图原图，元数据通过项目/系统/环境/会话/页面版本归属。
- 团队部署需要共享截图目录；切换数据源必须走显式迁移工具，不能运行时自动回退。

## 浏览器并发

一个会话 = 一个 `BrowserContext` + 一个 `Page` + 一个单线程执行器。不同用户绝不共享 `Page`。会话内的操作按顺序执行，超时的操作不得继续触发截图或绑定。

后续导航、DOM 变化与弹窗打开会形成独立页面版本。旧版本截图只能查看，不能绑定到当前功能。

## 元素识别

候选采集后按可见性、遮挡、空文本、语义、父子包含关系和组件归一逐层处理。动态类名哈希只作为短期定位信息，不作为长期身份。所有候选保留排除原因和发现批次，人工确认后才进入正式功能点。

## 删除与并发

树节点软删除，功能点用例仅解绑不删除，直接子节点上移。删除记录和审计记录用于恢复。跨系统移动不直接改父节点，需显式复制迁移。

实体通过 `revision` 乐观锁避免并发覆盖。当前本地存储按项目串行写入，PostgreSQL 使用事务和版本检查；后续批量操作应拆成独立的领域事务，不能整工作区不加约束覆盖。
